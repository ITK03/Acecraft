## 1. 基準系

| 項目 | 値 |
|---|---|
| 論理解像度 | **720 × 1280**（9:16 基準）。実機はこれをスケールして表示 |
| 座標原点 | 左上 (0,0)、Y は下方向が正 |
| プレイフィールド | X: 0〜720、Y: 0〜1280 |
| プレイヤー移動可能範囲 | X: 40〜680、Y: 300〜1180 |
| 論理FPS | **60固定**（物理・当たり判定は固定ステップ 1/60 秒） |
| 時間単位 | 本仕様書の秒数はすべて実時間秒 |

> 描画は可変FPSでもよいが、**弾の移動と衝突判定は必ず固定ステップ**で回すこと。
> 弾幕STGでフレーム依存の移動を書くと、端末差で難易度が変わり、リプレイもリーダーボードも成立しない。

## 2. クラフト（自機）

### 2.1 状態機械

```
                 ┌────────────────────────────────────┐
                 │                                    │
     [touch down]│                                    │[touch up]
          ┌──────▼──────┐                    ┌────────┴────────┐
   ┌─────►│    MOVE     │────[touch up]─────►│     DRAIN       │◄────┐
   │      │  移動+主砲   │                    │  ドレイン(吸収)   │     │
   │      └─────────────┘                    └────────┬────────┘     │
   │                                                  │              │
   │                                    [tap] かつ charge>0          │
   │                                                  │              │
   │                                         ┌────────▼────────┐     │
   └──────[counterDuration 経過]─────────────│    COUNTER      │     │
                                             │  カウンター発動中 │     │
                                             └─────────────────┘     │
                                                                     │
   起動時の初期状態 = DRAIN（指が触れていないため）─────────────────────┘
```

**遷移規則（厳密）**

| 現在 | 入力 | 次 | 備考 |
|---|---|---|---|
| MOVE | タッチ終了 | DRAIN | 即時 |
| DRAIN | タッチ開始 かつ `charge == 0` | MOVE | 通常の移動再開 |
| DRAIN | タッチ開始 かつ `charge > 0` | COUNTER | **カウンター発動** |
| COUNTER | `counterDuration` 経過 | MOVE（指が接地中） / DRAIN（離れている） | |

> **重要**: `charge > 0` の状態で画面に触れると必ずカウンターが出る。
> 「カウンター専用ボタン」は作らない。**入力はドラッグ1種類だけ**というのが本作の設計思想の中核。

### 2.2 移動

- MOVE / COUNTER 中: 指の移動量をそのままクラフトに加算（1:1 の相対移動）
  - **絶対追従（指の座標＝機体座標）にしないこと。** 指が機体を隠す
  - 追従補間: `pos += (targetPos - pos) * followLerp`（`followLerp = 0.5` [設計値]）
- DRAIN 中: 指が離れているため入力なし。**クラフトはその場に停止**
  - ただし慣性で `driftDamping = 0.85` を毎フレーム乗じて減速させる（急停止は手触りが悪い）

> 第1次ドキュメントの「吸収中は移動速度が落ちる（通常比55%）」は、**裏付けとなる情報源が見つからなかった**。
> そもそも「指を離す＝ドレイン」である以上、**吸収中は移動入力自体が存在しない**ため、
> 速度係数という概念が成立しない。
> リスクは「移動速度低下」ではなく「**移動そのものを放棄する**」ことで発生している。ここが本作の賢い点。
> （[!] 原作が「指を接地したまま静止しても吸収に入る」仕様なら話は変わる。実機確認が取れ次第この節を更新すること。）

### 2.3 当たり判定

- クラフトの当たり判定は **中心のコアのみ**。半径 `hitRadius`
- スプライト幅を 96px とした場合、`hitRadius = 6`（スプライト幅の約 6%）[設計値]
- 難易度別: Casual `8` / Normal `6` / Ace `5`
- **コア位置には常時、視認できるインジケータ（小さな光点）を表示する**

### 2.4 主砲（MOVE / COUNTER 中のみ発射）

| パラメータ | 値 | 備考 |
|---|---|---|
| `fireInterval` | 0.12 秒 | [設計値] |
| 初期弾数 | 2 | 中央からやや左右に平行 |
| 弾速 | 1400 px/秒（上方向） | |
| 1発ダメージ | `player.atk * 1.0` | |

- **DRAIN 中は主砲を撃たない**（攻撃と吸収は排他）[原作A]

## 3. ドレイン（吸収）システム — 本作の核

### 3.1 吸引判定

DRAIN 状態のとき、クラフト前方に扇形の吸引領域を生成する。

| パラメータ | 値 |
|---|---|
| 形状 | クラフト中心を頂点とする扇形 |
| `drainRadius` | 260 px [設計値] |
| `drainAngle` | 上方向 ±55°（合計110°）[設計値] |
| `drainPullSpeed` | 900 px/秒（クラフト方向へ引き寄せ）|
| 吸引の立ち上がり | DRAIN 遷移から 0.08 秒で全開（演出兼、誤爆防止）|

**判定対象**: `bullet.chargeable == true` の弾のみ。それ以外の弾は吸引領域を素通りし、通常通り当たる。

### 3.2 チャージ蓄積

```
チャージ弾が craft.hitRadius + 20 以内に到達 → 消滅 + charge += 1
charge の上限 = chargeMax = 30   [設計値]
```

- `charge` はカウンターの威力に直結する
- **`charge` はカウンター発動で 0 にリセットされる**
- ウェーブをまたいでも `charge` は保持する

### 3.3 オーバードライブゲージ

- チャージ弾1発吸収につき `ultGauge += 1`
- 主砲が敵にヒットした場合も `ultGauge += 0.15`（吸わないプレイでも溜まるように）[設計値]
- `ultGaugeMax = 100`
- MAX になると HUD のオーバードライブボタンが点灯し、任意タイミングで発動可能

### 3.4 カウンター

発動時:

1. `charge` の数だけカウンター弾を生成（パイロットのカウンター定義に従う）
2. **画面内の全ての敵弾を消去**（`charge >= counterClearThreshold` のとき。しきい値 = 10 [設計値]）
3. `counterDuration = 0.35` 秒の間、クラフトは**無敵**
4. `charge = 0`

ダメージ式:

```
counterDamage = player.atk * counterBaseRatio * (1 + charge * counterScale)

counterBaseRatio = 3.0    [設計値]
counterScale     = 0.08   [設計値]
```

→ charge 30 で `atk * 3.0 * 3.4 = atk * 10.2`。主砲10発分強。**「溜めて撃つ」が正解になる**バランス。

### 3.5 手触りの必須要件（ここを削ると全部無意味）

以下は「実装したかどうか」ではなく「気持ちいいかどうか」で判定する項目。**Phase 0 の合否はここで決まる。**

| 要素 | 要求 |
|---|---|
| 吸引の視覚 | 渦のパーティクル。チャージ弾は**加速しながら**吸い込まれる（等速はダメ） |
| 吸引の音 | 低音の吸引音。`charge` 増加に応じて**ピッチを段階的に上げる**（12段階以上） |
| チャージ表示 | クラフト周囲に光の輪。charge に比例して太く・明るく |
| カウンター発動 | **0.06秒のヒットストップ** + 画面フラッシュ + 弾消去の波紋 |
| カウンターの音 | 溜めた charge が多いほど重い音に差し替え（3段階以上） |
| 弾消去 | 消える弾は「消滅」ではなく**小さなスコア粒子に変換して自機に飛ばす** |

## 4. 弾システム

### 4.1 データ構造

```ts
interface Bullet {
  id: number
  active: boolean          // プーリング用
  faction: 'player' | 'enemy'
  x: number; y: number
  vx: number; vy: number
  ax: number; ay: number   // 加速度（曲がる弾用）
  radius: number           // 当たり判定半径
  damage: number
  chargeable: boolean      // ★ドレイン可能フラグ
  sprite: string
  outlineColor: string     // ★視認性のため必須
  pierce: number           // 残り貫通回数（-1で無限）
  lifetime: number
  homingTarget?: EntityRef
  homingStrength: number   // 0 = 直進
  onExpire?: 'none' | 'split' | 'explode'
}
```

### 4.2 チャージ弾の生成規則 [原作B]

**専用の敵を作らない。** 弾を生成する瞬間に確率でフラグを立てる。

```
chargeable = random() < waveConfig.chargeableRate
```

| 場面 | `chargeableRate` |
|---|---|
| 通常ウェーブ | 0.30 [設計値] |
| ボス戦 | 0.35 [設計値]（溜めて撃ち返す設計にするため高め） |
| 高難度ウェーブ | 0.20 |

> **0.15 を下回るとドレインが死に要素になり、0.45 を超えると弾幕が資源にしか見えなくなる。**
> この1パラメータがゲーム全体のテンポを決める。最優先で実測調整する。

### 4.3 プーリング（必須）

- 起動時に `Bullet` を **1200個** 事前確保。ランタイム生成は禁止
- 同時アクティブ上限: 敵弾 **600**、自弾 **400**
- 上限到達時は**最も古い弾を強制回収**（新しい弾を捨てない — 敵の攻撃が欠けるとパターンが崩れる）
- 画面外判定: プレイフィールドの外側 120px を超えたら回収

### 4.4 視認性ルール（原作の最大の弱点を潰す）

**すべての敵弾に例外なく適用する。**

1. 敵弾は必ず **2px の暗色アウトライン**（`#1a1020`）を持つ
2. チャージ弾は **マゼンタ系（`#FF3FA4`）に統一**。他のいかなる要素にもこの色相を使わない
3. 通常敵弾は **シアン〜白系（`#7FE8FF`）**
4. 背景レイヤーの上に **常時 `rgba(0,0,0,0.28)` の減光レイヤー**を敷き、その上に弾・敵・自機を描画
5. 設定に「背景演出を抑える」トグルを用意し、ONで減光を `0.45` に強化 + 背景アニメを停止

## 5. 敵とウェーブ

### 5.1 敵データ

```ts
interface EnemyDef {
  id: string
  hp: number
  scoreXp: number          // 撃破で得られる経験値
  sprite: string
  hitRadius: number
  moveScript: MoveScript   // 移動パターン
  fireScript: FireScript[] // 攻撃パターン（複数同時可）
  wrapAround: boolean      // ★画面下に抜けたら上部に再出現するか
  contactDamage: number
}
```

- **`wrapAround` は原作の重要な仕様** [原作B]。true の敵は画面下端を超えると Y を `-100` にリセットして再出現する
  → 「逃げ切れない、必ず倒す」という圧を作る。ウェーブが「敵を全滅させないと進まない」設計と噛み合う

### 5.2 移動スクリプト（最低限これだけあれば1章分は作れる）

| id | 挙動 |
|---|---|
| `straightDown` | 一定速度で下降 |
| `sineDown` | 下降しながら横に正弦波 |
| `enterAndHold` | 指定Yまで降下して停止、一定時間後に退場 |
| `swoop` | 弧を描いて突っ込み、画面外へ |
| `formationSlot` | 編隊の相対位置に追従（編隊リーダーが別途動く） |
| `chasePlayer` | プレイヤーX座標に緩慢に追従しながら下降 |

### 5.3 攻撃スクリプト（弾幕プリミティブ）

パターンは**プリミティブの組み合わせ**で定義する。個別に手続き型で書かない。

```ts
type FireScript = {
  pattern: 'aimed' | 'spread' | 'ring' | 'spiral' | 'laserBeam' | 'burst'
  count: number            // 一度に撃つ弾数
  spreadAngle: number      // deg
  speed: number
  interval: number         // 発射間隔(秒)
  cooldown: number         // バースト間の休止(秒)
  startDelay: number
  chargeableRate?: number  // 未指定ならウェーブ既定値
  bulletTemplate: string
}
```

| pattern | 説明 |
|---|---|
| `aimed` | プレイヤー方向へ `count` 発 |
| `spread` | 正面基準に `spreadAngle` 内で扇状に `count` 発 |
| `ring` | 全方位に等間隔 `count` 発 |
| `spiral` | `ring` を毎回 `rotStep` 度ずつ回転させながら連射 |
| `laserBeam` | 予告線 → 太いビーム。**予告0.7秒は必須** |
| `burst` | `count` 発を `interval` 秒おきに連射 |

### 5.4 ウェーブ定義

```ts
interface WaveDef {
  index: number
  spawns: Array<{
    enemyId: string
    count: number
    formation: 'line' | 'v' | 'arc' | 'random' | 'sides'
    spawnDelay: number     // ウェーブ開始からの秒
    interval: number       // 個体間の湧き間隔
    entryX?: number
  }>
  chargeableRate: number
  clearCondition: 'killAll' | 'survive'
  surviveDuration?: number
  postWaveHeal: number     // ★クリア時のHP回復量（原作の弱点を潰す）
}
```

- `clearCondition: 'killAll'` が基本 [原作A]
- **`postWaveHeal` を必ず設定する。** 原作最大の不満点への対処
  - 推奨: 通常ウェーブ `maxHp * 0.05`、ボス直前ウェーブ `maxHp * 0.20` [設計値]

### 5.5 ステージ定義

```ts
interface StageDef {
  id: string               // "1-3"
  chapter: number
  waves: WaveDef[]         // 10〜20  [原作A]
  boss: BossDef
  suggestedCp: number      // ★推奨戦力。下回ると敵HP/ATKに補正がかかる
  starConditions: [StarCond, StarCond, StarCond]  // ★3条件 [原作A]
  staminaCost: 5           // [原作A]
}
```

**推奨CP補正 [設計値]**

```
ratio = playerCp / suggestedCp
enemyScale = clamp(1 / ratio, 0.7, 1.6)   // 戦力不足なら敵が硬く痛くなる
```

**星条件の例**（原作は3条件 [A]、内容は自由）

1. ステージクリア
2. 被弾3回以下
3. 制限時間 `X` 秒以内にクリア

## 6. ボス

```ts
interface BossDef {
  id: string
  hpBars: number           // ★HPバーの本数。章ボスは 20 など [原作B]
  hpPerBar: number
  phases: BossPhase[]      // バー残量で遷移
  entryCutscene: number    // 登場演出秒数（この間は無敵かつ攻撃しない）
}

interface BossPhase {
  fromHpRatio: number      // 1.0 → 0.6 など
  patterns: FireScript[]
  moveScript: MoveScript
  enrageAtSeconds?: number // 長引いたら弾幕強化
}
```

**設計要件**

- ボスの各フェーズには **必ず1つ「チャージ弾が多い大技」を入れる**
  → プレイヤーが「ここで溜めて、ここで返す」段取りを学習できる
- 大技の前には **1.0秒の予告演出**（発光 + SE）
- フェーズ遷移時に **全弾消去 + 0.5秒の硬直**（プレイヤーの立て直し時間）

### 7.1 スロット

|---|---|---|
| モジュール（攻撃） | **4** | 2（主砲・ドレイン/カウンター）→ **自由枠2** |
| チップ（補助） | **4** | 0 |

[原作A]。時間迷走相当のモードではモジュール枠を **6** に拡張する [原作A]。

### 7.2 データ

```ts
interface ModuleDef {
  id: string
  name: string
  maxLevel: 3
  unlockAtPlayerLevel: number   // ★アカウントLvで解放 [原作A]
  levels: [ModuleStats, ModuleStats, ModuleStats]
  evolvesTo?: string            // オーバーモジュールID
  evolveRequiresChip?: string   // ★必要チップID
  tags: ('single' | 'aoe' | 'orbit' | 'trap' | 'homing' | 'melee')[]
}

interface ChipDef {
  id: string
  name: string
  maxLevel: 3
  unlockAtPlayerLevel: number
  levels: StatModifier[]
}
```

### 7.3 進化ルール [原作A]

```
モジュール X が Lv3（MAX）
　かつ チップ Y を1つ以上所持
　かつ プレイヤーレベルが解放条件を満たす
　→ 次のレベルアップ3択に「オーバーモジュール X+」が確定で1枠出現
　→ 選択すると X が X+ に置き換わる（スロットは消費しない）
```

### 7.4 3択の抽選アルゴリズム

```
候補プール = 
   (解放済みモジュール ∩ (空きスロットあり OR 既所持かつLv<3))
 + (解放済みチップ     ∩ (空きスロットあり OR 既所持かつLv<3))

1. 進化条件を満たすオーバーモジュールがあれば 1枠を確定で確保
2. 残り枠を候補プールから重み付き抽選（重複なし）
   重み = baseWeight * rarityWeight * situationBonus
3. 候補が3未満なら「小回復」「ゴールド」などのフォールバック報酬で埋める
```

**重み設計 [設計値]**

| 条件 | 倍率 |
|---|---|
| 未所持モジュール（自由枠がある） | 1.5 |
| 所持モジュールの強化 | 1.0 |
| 未所持チップ | 1.2 |
| 所持チップの強化 | 0.9 |
| 進化トリガーになるチップを未所持 | **2.0**（進化を成立しやすくする） |

> 原作はアタッチメント間の格差が大きく、それがランの起伏を作っている [原作B]。
> **意図的にフラットにしないこと。** ただし「引きが悪いと詰む」ことがないよう、
> フォールバック報酬と `postWaveHeal` で下振れを救う。

## 9. ダメージ計算

```
// プレイヤー → 敵
raw       = atk * skillRatio * (1 + atkBonus)
crit      = random() < critRate ? critDamage : 1.0
elemental = elementMultiplier(playerElement, enemyElement)
damage    = raw * crit * elemental * enemyDefFactor

enemyDefFactor = 100 / (100 + enemy.def)

// 敵 → プレイヤー
damage = bullet.damage * (1 - min(damageReduction, 0.75))
```

| 定数 | 値 |
|---|---|
| `critRate` 初期 | 0.05 |
| `critDamage` | 1.5 |
| `elementMultiplier` | 有利 1.2 / 等倍 1.0 / 不利 0.85 [設計値] |
| 被ダメージ軽減上限 | 75% |

**属性 4種（原作準拠の構造、名称は独自）[原作A]**

```
Solar → Sand → Gale → Mist → Solar  （リング状の有利関係）
```

### 残機・HP

- クラフト1機あたり **HP 100**、被弾ダメージは弾種依存（雑魚弾 12 / ボス弾 20 / 接触 25）[設計値]
- ステージには **3機**編成して持ち込む [原作準拠]
- 1機撃墜 → 次の機体に交代（1.5秒の無敵時間つきで復帰）
- **2機撃墜時点で、広告視聴 or 課金通貨で1機復活**（1ステージ1回まで）[原作B]
- 全機撃墜でステージ失敗

## 12. Phase 0 受け入れ基準

> **Phase 0 の目的は「面白いかを判定すること」であり、機能を揃えることではない。**
> 以下がすべて満たされて初めて Phase 1 に進む。1つでも欠けたら進まない。

### 機能チェック

- [ ] ドラッグでクラフトが相対移動する（絶対追従ではない）
- [ ] MOVE 中は主砲が自動連射される
- [ ] 指を離すと DRAIN に遷移し、扇形の吸引が発生する
- [ ] チャージ弾（マゼンタ）のみが吸い込まれ、通常弾（シアン）は素通りして当たる
- [ ] 吸収数に応じて自機周囲のチャージリングが成長する
- [ ] `charge > 0` の状態でタップするとカウンターが発動する
- [ ] カウンターが画面内の敵弾を消去し、charge に比例したダメージを与える
- [ ] 敵1種（`wrapAround` 挙動を含む）＋ボス1体が動作する
- [ ] 弾は完全にプーリングされ、600発同時で60fpsを維持する
- [ ] 全敵弾にアウトラインが付き、背景に減光レイヤーが乗っている

### 体験チェック（**これが本番**）

- [ ] **30秒プレイして「もう1回」と思えるか**
- [ ] カウンター発動時にヒットストップと音の変化があり、明確に気持ちいいか
- [ ] 「今は吸うべきか、撃つべきか」の判断が**毎秒発生している**か
- [ ] 溜め切って大きなカウンターを返した瞬間に、思わず声が出るか
- [ ] 敵弾が見えなくて死んだ、と感じる場面が**一度もない**か

> **判定基準**: 開発者以外の人間3人に30秒ずつ遊ばせ、2人以上が自発的に2回目を要求すること。
> ここが弱ければ、アートもガチャもステージ100種も**すべて無意味**。作り直すか、企画を中止する。
