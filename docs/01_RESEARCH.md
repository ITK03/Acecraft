## 1. 第1次リサーチからの訂正・重要追記（最優先で読む）

第1次ドキュメントは方向性としては正しいが、**コアループの理解に実装を左右する誤りが3点**ある。

### ❌ 訂正1: アタッチメントは「ただの3択積み上げ」ではない。**スロット制**である

第1次では「レベルアップで3択→そのステージ中ずっと継続」とだけ書かれていたが、実際は
**攻撃アタッチメント4スロット + 補助アタッチメント（プラグイン）4スロットの 4:4 構成** [A]。

- 攻撃スロット4のうち、**開始時点で2つは埋まっている**（機体固有の「主砲」と「吸収／スタント」）[B]
  → プレイヤーがランで新規に取れる攻撃アタッチメントは実質 **2枠**
- 補助（プラグイン）は4枠すべて自由 [B]
- スロットが埋まった後は、既存のものを Lv2 → Lv3 に強化する選択肢しか出なくなる（Vampire Survivors と同型）[C]

**これは設計上決定的に重要**。取り放題ではなく「2枠しかない攻撃枠に何を入れるか」という**枠の奪い合い**がビルドの本体になっている。第1次の理解のまま実装すると、ローグライトの戦略性が丸ごと消える。

### ❌ 訂正2: Evo（進化）は「攻撃2種の組み合わせ」ではない。**攻撃MAX × 対応プラグイン**である

- 攻撃アタッチメントを **Lv3（MAX）まで上げ**、かつ**対応する補助プラグインを所持**していると進化する [A]
- 実例: 「バズ罠（水色）を3回取得 + 砂時計プラグインを1回取得 → 紫のバズ罠に進化」 [B]
- 実例: 「エアストライクI + バズ罠」が上位進化の組み合わせとして言及されている [B][!]（前者と食い違うため、進化テーブルは複数パターン存在する可能性）

つまり **Vampire Survivors の「武器MAX + 対応パッシブ」方式そのもの**。ここを間違えると進化が一生成立しない。

### ❌ 訂正3: 「パイロット全滅」の意味。**ステージには複数機を持ち込む**

第1次の「全滅時1回だけコンティニュー」は正しいが、その前提が抜けている。

- ステージには複数の機体（パイロット）を編成して持ち込む [A]
- **2機撃墜された時点で、広告視聴 or ダイヤ消費で1機復活できる** [B]
- 全滅前にボスを倒せばクリア [A]

→ HP制ではなく**残機制に近い**。この差は難易度設計とリトライ体験を大きく変える。

## 3. コアゲームプレイ（インゲーム）— 完全再現対象

### 3.1 操作系 [A]

```
指を画面に置いてドラッグ → 自機が指に追従移動、主砲は常時オート連射
指を離す               → 吸収（Spitfire）モードへ移行。前方に渦が発生しピンク弾を吸い込む
吸収後にタップ         → スタント（カウンター攻撃）発動
ウルトボタン           → ゲージMAXで必殺技
支援ボタン             → クールタイム制でパートナーパイロットを呼び出し
```

**設計の核心（ここを外すとゲームが別物になる）:**

1. **攻撃と吸収は排他** [A]。撃っている間は吸えない、吸っている間は撃てない
2. **何も操作しないと自動的に吸収モードになる** [B]
   → 「指を離す」は明示的な入力ではなく、**移動をやめること**そのものが吸収の発動条件
   → つまり **「動く＝攻撃、止まる＝吸収」** という、ボタン0個で成立する二択
3. 吸収中は無敵ではない。ピンク弾以外は普通に当たる [A]
4. 上級者の立ち回りは「吸う前に退路を作る → 一拍ためる → カウンター」 [B]

> **実装上の最重要ポイント**: 「離す＝吸収」ではなく「**指が静止している＝吸収**」に近い挙動である可能性が高い [!]。
> ドラッグ中に指を止めた場合の挙動（吸収に入るか／移動状態を維持するか）は実測で決めるべき最重要パラメータ。
> 本仕様書では **「指を離す = 吸収」を採用**（実装が明確で、誤爆が少ないため）。

### 3.2 弾の種類 [A]

| 弾 | 挙動 |
|---|---|
| **ピンク弾** | 吸収可能。吸うとエネルギーゲージ蓄積 |
| その他の弾 | 吸収不可。回避のみ |

- ピンク弾は「特定の敵が撃つ」のではなく、**同じ敵の同じ攻撃でも、弾ごとに確率でピンクになる** [B]
  - 実例: 敵「2 of Clubs」はクラブ型の弾を2発直線に投げるが、**片方または両方がピンクになる確率がある**
  - → 実装は「弾生成時に確率でピンクフラグを立てる」でよい。専用の敵を用意する必要はない

### 3.3 吸収 → 反撃ループ [A]

```
ピンク弾を吸収
  ↓ エネルギーゲージ蓄積
スタント（カウンター）発動 ／ ウルトゲージにも寄与
  ↓
画面上の敵弾を消しつつ大ダメージ
```

- スタントはパイロットごとに固有 [A]（例: 一定時間主砲を貫通弾に強化 / 追跡ミサイル一斉発射）
- 一部パイロットは**パッシブが吸収数をトリガーにする**（例: 一定数吸収後に交差サブ弾を発射）[A]
- ウルトは「ボム」相当。敵弾を消しながら広範囲ダメージを与えるものが多い [A]

### 3.4 ウェーブ／ステージ構造 [A]

```
1ステージ = 10〜20ウェーブ
  ├ 各ウェーブ: 敵を全滅させるまで次に進めない
  ├ 敵は画面下に抜けても最上部に再出現する（＝殲滅必須）
  ├ 途中に地形・障害物ギミック
  └ 最終ウェーブ: ボス
```

- ボスは章の途中にも出る。例: 1章では **1-2 と 1-5 の両方にボス**がいる [B]
- 章のラスボスは HP バーが複数本（例: Smiley = **HPバー20本**）[B]
  → ボス HP は「N本のバー」として表現するのが原作流。実装もこの形が扱いやすい
- クリア条件: 全機撃墜される前にボスを倒す [A]
- **コンティニュー: 2機撃墜時点で、広告視聴 or ダイヤで1機復活** [B]

### 3.5 星3・収集要素 [A]

- 各ステージに **3つのクリア条件**（例: 被弾N回以下 / 制限時間内 / 特定行動）→ 1〜3星
- **ノーダメージクリア**で「完全勝利の証」としてボスポートレートを獲得 [B]
- ステージには **Clues（手がかり）** という収集要素が別途存在 [B]

### 4.5 攻略上の定石（バランス設計のヒント）[B]

- 序盤は「火力アップ」より「**攻撃パターンが増える**」アタッチメントを優先すべき、とされる
  → 縦以外の方向をカバーできるため
- S級を2つ引ければ勝ち確、というほど**アタッチメント間の格差は大きい**
  → 原作は意図的にフラットにしていない。**引きの強弱がランの面白さを作っている**
- 状況依存（単体/複数、近距離/遠距離）で最適解が変わる設計

## 5. メタ育成（アウトゲーム）

### 5.1 パイロット

| 要素 | 内容 | ラベル |
|---|---|---|
| レアリティ | A < S < SP < SS | [A] |
| 初期人数 | 8人 → 1年で20人以上に拡張 | [A] |
| 属性 | Solaris / Sandstorm / Cyclone / Nimbus の4種 | [A] |
| 射撃タイプ | Sharpshot / Crusher / Vanguard の3種 | [A] |
| 保有スキル | 主砲・スタント・ウルト・パッシブ（**パッシブはSランク以上のみ**） | [A] |
| 強化 | レベルアップ（訓練）、Amplify（凸／限界突破）でステータス＋スキル強化 | [A] |
| 育成推奨 | 全員育てず **3〜4人に集中**するのが定石 | [B] |

**具体例（設計の参考として。名称・意匠は流用しない）**

- エルザ（S・射撃特化型）
  - 主砲: 高速弾2発を前方に
  - スタント「乱射」: 一定時間、主砲が貫通弾になる
  - パッシブ「全力射撃」: 一定数のピンク弾を吸収後、交差する2発のサブ弾を発射
  - ウルト「野生の交響曲」: 火炎機銃2基を召喚しクロスファイア
- プリス（レーザー型）
  - 主砲「ハイパーラインビーム」: 前方へ**弾をブロックできる**レーザーを継続照射
  - スタント「プレデターシグナル」: 大量の追跡ミサイル
  - パッシブ「オーバーロードプロトコル」: 主砲ヒットでエネルギー蓄積、満タンで自動ブラスト
  - ウルト「ゾーンイレイザー」: 低速前進するエネルギーボム。弾をブロックしつつ持続ダメージ

> **設計の要点（第1次の指摘は正しい）**: 性能差の大半を「**主砲の射角パターン**」で作っている。
> 実装コストが低く体感差が大きい。加えて本作は「弾をブロックできる攻撃」を持たせることで、
> 攻撃＝防御という本作固有の価値観を全キャラに通している。

### 5.2 支援機（Wingman）[A]

- 1パイロットにつき **2機まで**装備。自機の左右に配置され自動攻撃
- 攻撃モードを選択可能 [B]
- 属性を持ち、**パイロットと同属性なら基礎ステータス +25%** [B]
- S級パイロット専用の **シグネチャー支援機** が存在し、専用効果が付く [B]
- 重複入手で昇格（ランクアップ）できる [B]
- 恒常ガチャ「パイロット選抜」からパイロットと同じ枠で排出される [A]

### 5.3 支援（パートナー召喚）[A]

- 他のパイロットを呼び出して攻撃してもらう。**クールタイム制**
- **組み合わせが固定されており、相手パイロットを所持していないと使えない**
  → 明確なガチャ誘導装置

### 5.4 装備・エンブレム [B]

| 部位 | 主ステータス |
|---|---|
| 鍵（key）／指輪（ring） | ATK |
| 手袋（gloves）／靴（shoes） | DEF |
| ジャケット（jacket）／ズボン（pants） | PB [!]（略称の意味は未確認） |

- 装備は**全パイロット共通**。強化レベルは持ち替えても引き継がれる [B]
- 重複入手品は**融合**して上位化 [A]
- エンブレムを装備してステータス強化。**エンブレム工房**で融合、**ハサミ**で属性変更 [B]
- **Teslarite（テスララライト）** という別枠の装備品も存在 [B]
- 複数の編成プランを保存可能 [B]
- クリスタル強化で全体ステータス底上げ [B]
- **Base Tune-Up**（機体基礎強化）で ATK / DEF / HP を上げる [B]

### 5.5 ペット（2026年2月11日実装）[A]

- 植物モチーフの戦闘パートナー
- **メインペット2体 + アシストペット4体（メイン1体につき2体）= 計6体**
- メインが戦闘ルート（挙動パターン）を決め、アシストが追従
- レアリティ: B < A < S < SS < SSS

> クローンでは初期実装不要。ただし**将来の拡張スロットとして設計だけ空けておく**（第1次の判断に同意）。

### 7.1 ガチャ [A]

## 8. 原作の弱点（＝クローンの差別化余地）

レビューで繰り返し指摘されている点 [A/B]：

1. **明るい背景ステージで弾が見えない** — 視認性が致命的に悪い場面がある [B]
2. **回復手段が乏しい** — 回復系アタッチメントはあるが回復量が微量で機能していない [B]
3. **難易度が「激ムズ」** — 達成感はあるが、ライト層の離脱要因 [B]
4. **リセマラ不可** — アカウント削除・再インストールでも続きから始まる [B]
5. **ガチャ解放が遠い** — 操作練習 + ステージ1クリア後にようやく解放 [B]
6. **限定ガチャがダイヤ限定**でチケットが使えない [A]
7. **初回DL 1.87GB** [B]

### クローンで取れるポジション

| 原作の弱点 | クローンの解 |
|---|---|
| 弾が見えない | 背景に強制減光レイヤー、弾に必ずアウトライン、「背景演出オフ」設定 |
| 回復が渋い | ウェーブクリアごとの小回復を**実効性のある量**で入れる |
| 激ムズ | 難易度選択（Casual / Normal / Ace）。当たり判定サイズを難易度で変える |
| リセマラ不可 | ゲスト即リセット可、チュートリアル3分でガチャ到達 |
| 1.87GB | **200〜400MB** を目標に。インストール障壁の低さは最大の武器 |

## 10. 法的方針（第1次の結論を維持・補強）

**「システムは100%再現、ガワ（世界観・キャラ・アセット・名称）は完全自作」**

| 再現してよい | 触ってはいけない |
|---|---|
| ゲームシステム・ルール・メカニクス | 「ACECRAFT / エースクラフト」の名称・ロゴ（商標） |
| 数値バランス、UIレイアウト構造、進行フロー | エコー、ジョイ、エルザ等のキャラ名・デザイン |
| 1930年代ラバーホース調という「様式」 | 画像 / BGM / SE / エフェクト等の実アセット |
| スロット構成・進化ルール等の設計思想 | 「クラウディア」等の固有名詞、ストーリーテキスト |
| | **コラボIP（トムとジェリー、ルーニー・テューンズ、悟空）— 絶対に近寄らない** |
| | Cuphead のキャラ・具体的意匠（原作自体が孫引き元） |

補強点: 開発元が **MOONTON（テンセント系）子会社**である以上、名称・意匠の模倣リスクは通常より高く見積もるべき。
**用語も独自化する**（例: 吸収→「ドレイン」、スタント→「カウンター」、支援機→「エスコート」）。本仕様書では以降この独自用語を使う。
